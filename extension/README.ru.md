# Расширение Chromium для passkeys

**Языки:** [English](README.md) · Русский

Это руководство хранится рядом с `extension/chromium/` и описывает браузерное расширение, а не ядро Keyward. См. [руководство core](../docs/core/README.ru.md).

## Назначение

Расширение позволяет сайтам Chromium использовать passkeys из vault Keyward и сохранять туда новые. Оно работает только вместе с приложением Keyward для macOS. Обрабатываются вызовы WebAuthn `navigator.credentials.get/create` с `publicKey`; расширение не заполняет пароли, не меняет содержимое страниц и не добавляет общие функции браузера.

Установите [опубликованное расширение Keyward](https://chromewebstore.google.com/detail/keyward/codlckblccbcnadacdnoieimkmdieajg) в Chrome или другой совместимый Chromium-браузер. Также установите/запустите приложение Keyward для macOS: `make install` устанавливает native messaging host (`me.loper`) и регистрирует мост браузера. Без host/app запросы passkey переходят к штатному механизму браузера.

## Pairing — первая церемония доверия

Pairing разрешает конкретный публичный ключ, хранящийся в расширении, а не только его extension ID. Расширение создаёт неэкспортируемый ECDSA P-256 ключ и подписывает запросы; приложение проверяет подпись и наличие явного pairing. Список сохраняется в скрытой записи личного vault владельца — не в локальном файле, который другой процесс того же пользователя может незаметно подменить, и не в общей записи организации. Маркер «hidden» скрывает запись только из обычных списков Keyward: она синхронизируется как обычный vault item и может быть видна в веб-интерфейсе сервера.

1. Разблокируйте vault и оставьте приложение Keyward открытым.
2. В Chromium откройте сайт, который запрашивает регистрацию или использование passkey. Расширение инициирует pairing и показывает **пять слов**; приложение отображает ожидающий запрос для этого браузера.
3. Сверьте все слова и проверьте, что браузер/устройство в запросе Keyward совпадают с теми, которые вы только что открыли. Не подтверждайте запрос, который сами не инициировали. Ожидающая заявка истекает через 10 минут.
4. Подтвердите соответствующую заявку Touch ID в приложении либо CLI-командой ниже. Слова на экране расширения и приложения должны совпасть точно.
5. После pairing браузер отображается в **Settings → Browsers** с именем устройства и временем последнего использования.

Управление из CLI:

```sh
keyward extension list       # связанные и ожидающие расширения; слова для сравнения
keyward extension pair       # связать единственную ожидающую заявку
keyward extension pair 1     # выбрать ожидающую строку по номеру
keyward extension unpair 1   # отозвать pairing строки по номеру
```

Используйте номер из текущего вывода `list`: состав ожидающих и связанных строк меняется. Pairing всегда является явным действием с подтверждением Touch ID. Удалите pairing, если профиль браузера удалён, скомпрометирован или больше не нужен.

## Вход и регистрация

- **Вход:** сайт просит passkey; Keyward показывает подходящие записи/аккаунты vault. Выберите аккаунт и подтвердите Touch ID в приложении. Браузер получает WebAuthn-ответ/подпись, но не приватный ключ.
- **Регистрация:** когда сайт просит создать passkey, выберите новую login-запись или существующую запись для этого сайта. Подтвердите Touch ID; Keyward сохраняет passkey в Bitwarden-совместимом формате в vault.
- **Другим способом:** передаёт запрос штатной WebAuthn-реализации браузера.

В запросе указаны origin/сайт и аккаунт. Если origin или аккаунт не соответствуют вашему действию — откажитесь. Мост проверяет подпись запроса, свежесть и защиту от повторного воспроизведения.

## Permissions и приватность

Расширение использует `nativeMessaging` для связи с приложением и `storage` только для `chrome.storage.session`, пока открыт chooser. Content scripts работают на HTTPS и localhost; скрипт в основном мире перехватывает лишь WebAuthn-вызовы с `publicKey`, только в верхнем frame. Изолированный bridge берёт origin от browser sender, а не из данных страницы. Нет `tabs`, `scripting`, `webRequest`, широких host permissions, remote code или аналитики. Параметры запроса и подписи chooser хранятся только в сессионной памяти браузера и очищаются после запроса/закрытия браузера.

Канал native messaging между браузером и приложением зашифрован. Данные идут только в Keyward на этом же компьютере, не разработчику и не третьим сторонам. Приватный ключ остаётся в приложении. Все типы данных и ограничения описаны в [политике приватности](../docs/extension-privacy.md).

## Если что-то не работает

- **Нет pairing-запроса:** проверьте, что приложение/daemon запущены, vault разблокирован, официальное расширение включено, а `make install` поставил native host; затем инициируйте новый WebAuthn-запрос.
- **Слова не совпадают:** отмените pairing. Не подтверждайте; закройте и откройте запрос заново и сравните слова повторно.
- **Расширение работает только в одном профиле:** установите расширение и выполните pairing отдельно в каждом профиле. Native host регистрируется для установленного браузера; если браузер установлен после Keyward, переустановите приложение/мост и перезапустите этот браузер.
- **Passkey не предлагается:** проверьте, что vault содержит соответствующий passkey/login для сайта и запрос относится к поддерживаемой WebAuthn-операции. «Другим способом» использует provider браузера.
- **Удалить устаревший pairing:** Settings → Browsers → удалить либо `keyward extension list`, затем `keyward extension unpair <номер>`.

Pairing не даёт расширению доступ ко всем паролям vault. Он разрешает подписанные WebAuthn-запросы от ключа расширения; выбор passkey и подпись остаются в приложении и требуют подтверждения пользователя.

WebAuthn-запросы conditional/autofill и запросы, явно требующие cross-platform authenticator, используют штатный provider браузера. Keyward не заменяет все сценарии WebAuthn.
