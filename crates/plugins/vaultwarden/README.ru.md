# Административный плагин Vaultwarden

**Языки:** [English](README.md) · Русский

Это руководство описывает отдельно устанавливаемый плагин `crates/plugins/vaultwarden/`. Включите его в Настройки → Плагины после просмотра разрешений. Это клиент административной панели сервера Vaultwarden, а не управление локальным аккаунтом Keyward. Общая архитектура находится в [руководстве core](../../../docs/core/README.ru.md).

## Назначение и требования

Плагин обращается к панели `/admin` сервера **только по HTTPS**. На сервере панель должна быть включена через `ADMIN_TOKEN`; Keyward запрашивает сам admin token, а не его Argon2 hash. Адрес сервера берётся из настроенного аккаунта vault, поэтому сначала нужно настроить аккаунт/сервер. Admin-запросы имеют привилегии: используйте отдельный административный token и включайте плагин только для сервера, которым управляете.

В этой интеграции нет item fields `kw-*`: токен — собственный credential плагина, а не схема подключения на записи. Он хранится в macOS Keychain, запечатанный ключом, производным от разблокированного vault, и читается за gate Touch ID/user presence приложения. Во время unlock Keyward проверяет токен через панель до сохранения; отвергнутый токен не записывается. **Lock panel** завершает сессию и удаляет token из Keychain; повторная разблокировка требует вставить его заново. Событие блокировки core также блокирует UI/сессию плагина.

## Разблокировка и состояние

Откройте **Vaultwarden** в приложении, вставьте серверный `ADMIN_TOKEN` и выберите **Unlock**. Плагин выполняет login по HTTPS и сохраняет проверенный credential в Keychain. Он отображает, если панель выключена/недоступна, включён rate limit, токен неверен или сессию нельзя обновить. После серии неудачных попыток сервер может ограничить вход; выждите время вместо постоянных повторов.

## Пользователи

Страница Users показывает email/name, состояние enabled/invited, подтверждение email, двухфакторную защиту, даты создания/последней активности и членство в организациях. Доступны приглашение по email (письмо отправляет Vaultwarden, пользователь сам создаёт аккаунт), повторное приглашение и действия, допустимые в текущем состоянии:

- включить или отключить пользователя;
- принудительно завершить сессии на всех устройствах;
- снять двухфакторную регистрацию;
- удалить пользователя;
- назначить разрешённую роль в организации.

Отключение завершает вход пользователя и запрещает новый до повторного включения. Deauthenticate заставляет заново войти, но не удаляет аккаунт. Снятие 2FA ослабляет аккаунт, пока пользователь не настроит её снова. **Удаление пользователя безвозвратно удаляет его записи сервера, вложения и членство. Отменить это нельзя.** Внимательно проверьте цель и текст подтверждения.

Для членства в организации UI различает полномочия администратора. Если текущий администратор владелец/управляет организацией, он может приглашать/добавлять и удалять участников. Иначе панель может менять поддерживаемые роли, а изменения состава должен выполнять владелец/администратор организации: добавление участника даёт ему доступ к зашифрованным материалам организации. Разрешённые роли зависят от plugin/server; произвольная custom role не создаётся.

## Организации

Раздел Organizations объединяет участников по организациям и показывает количество owner/member, статус и роль. Удаление организации удаляет её записи, коллекции и членство для всех пользователей и **необратимо**. Перед удалением сверяйте точное имя.

## Настройки сервера

Настройки динамически читаются из административной страницы конфигурации и группируются так, как их предоставляет Vaultwarden (например general/advanced, SMTP, SSO, push, jobs и другие группы конкретного сервера). Изменяемые значения бывают text, number, password, checkbox. UI показывает panel-значение, default и признак override.

Параметры, заданные environment variables, видны только для чтения; менять их нужно в окружении сервера, иногда с перезапуском. При сохранении плагин отправляет **полный текущий набор редактируемых настроек** с внесёнными изменениями: сервер заменяет конфигурацию целиком. Значения password не раскрываются; пустое поле означает оставить текущий пароль. **Reset settings** удаляет panel overrides и возвращает defaults/environment; это широкое действие без отмены. Перед save/reset проверьте конфигурацию и подтверждение.

## Инструменты сервера

- **Database backup:** вызывает резервирование базы на сервере. Сейчас поддерживается только SQLite; Vaultwarden создаёт копию рядом со своей базой. Keyward не скачивает и не проверяет эту копию. Настройте отдельное серверное хранение и offsite backup.
- **Test SMTP:** просит сервер отправить тестовое письмо на указанный адрес. Перед отправкой проверьте адрес.
- **Lock panel:** забывает сохранённый admin token и завершает текущую панельную сессию.

## Permissions и движение данных

Manifest запрашивает `keychain` и `network`. Плагин использует адрес настроенного сервера и admin token для API Vaultwarden; vault items/пароли он не читает. Исходный token хранится в Keychain с защитой на основе ключа vault и извлекается только после необходимой проверки user presence/Touch ID. Проверка HTTPS обязательна, потому что token передаётся в запросах панели. Привилегированные API-вызовы неизбежно получает сервер.

## Ошибки и безопасность

Без admin token, при отключённой панели, неверном URL/сертификате или недоступном сервере разблокировка не пройдёт. Не отключайте проверку HTTPS и не помещайте admin token в логи, shell history, скриншоты или тикеты. Удаление пользователей/организаций, снятие 2FA, отключение учётных записей и reset настроек влияют на безопасность/доступность; точно следуйте тексту подтверждения. Плагин экспериментальный, не аудирован; проверяйте его на версии Vaultwarden, которой управляете.
