# SSH-плагин

**Языки:** [English](README.md) · Русский

Это руководство принадлежит `crates/plugins/ssh/` и описывает только SSH-интеграцию. Общее устройство аккаунта, daemon и vault находится в [руководстве ядра](../../../docs/core/README.ru.md).

## Назначение и модель

Плагин сопоставляет адрес назначения с SSH-ключом в vault и поднимает для этого хоста отдельный сокет агента. Сокет предлагает ровно одну identity, поэтому OpenSSH не перебирает все ключи из vault. Приватный ключ находится у daemon, а подпись выполняется ядром через capability `ssh_sign`. Плагин получает результат подписи, но не байты приватного ключа.

После установки включите SSH в Настройки → Плагины. Таблица маршрутов перестраивается из разблокированных записей после unlock и изменения элементов. При перестроении существующие agent sockets удаляются, чтобы они не отдавали старый ключ; перед следующим использованием снова выполните resolve (обычно через конфигурацию OpenSSH ниже). При lock плагин закрывает terminal sessions, удаляет per-host/shared sockets и очищает записи и маршруты из памяти.

## Привязка ключа к хостам

В разделе **SSH → Routes** выберите ключ и привяжите к нему один или несколько шаблонов через запятую. Плагин хранит маршрутизирующие метаданные как custom fields той же записи vault. Префикс `kw-` обозначает метаданные, принадлежащие интеграции: это не даёт принять несвязанное поле пользователя `host`, `user` или `port` за конфигурацию SSH, сохраняет данные на самой записи при синхронизации и помогает границе core/plugin различать поля интеграции. Новых колонок на сервере при этом не создаётся.

| Custom field | Значение и формат |
|---|---|
| `kw-host` | Список маршрутов; шаблоны `[user@]host[:port]`, разделённые запятыми. Пример: `*.example.net, git.example.com, admin@node1.*:2222`. Пустое значение снимает привязку. |
| `kw-user` | Логин по умолчанию для terminal/health, если в шаблоне нет пользователя. Сам по себе не условие совпадения. |
| `kw-port` | Порт по умолчанию для terminal/health, если в шаблоне нет порта. Целое число 1–65535. |
| `kw-confirm` | При значении `yes`, `true`, `1` или `on` требует подтверждения каждой подписи этим ключом. |
| `kw-hostkey` | Необязательный отпечаток/pin ключа сервера. Терминал проверяет его; агент хоста проверяет при получении корректного session binding от SSH-клиента. Несовпадение приводит к отказу. |
| `kw-knownhosts` | Служебные сохранённые host-key записи интеграции. Создаются и обслуживаются SSH-потоком; не редактируйте сериализованное значение вручную. |
| `kw-cert` | Метаданные роли сертификата присутствуют в модели маршрута, но плагин сейчас не выпускает Vault SSH-сертификаты. |

По возможности используйте редактор Routes: он проверяет логин и порт и записывает поля маршрута через приложение. Можно создать ключ Ed25519 или RSA либо импортировать приватный ключ OpenSSH (включая зашифрованный с passphrase) или RSA PEM (PKCS#1/PKCS#8). Зашифрованный PEM не поддерживается. При импорте поддерживаемый ключ преобразуется в OpenSSH перед сохранением. После генерации/замены ключа обновите публичный ключ на серверах: прежний `authorized_keys` не начнёт доверять новому ключу автоматически.

### Правила совпадения

Парсер делит `kw-host` по запятым и проверяет каждый шаблон. Поддерживается wildcard `*`. Маршрут подходит, только когда совпал шаблон хоста и выполнены заданные ограничения пользователя/порта из запроса SSH. Приоритет сравнивается по полям: точное имя хоста выше wildcard, затем более длинная литеральная часть, затем наличие пользователя и порта. Равные по специфичности варианты помечаются неоднозначностью. Реализация возвращает детерминированного победителя (по имени записи, затем шаблону) и показывает предупреждение; считайте его ошибкой конфигурации и устраните конфликт.

`keyward hosts` показывает таблицу маршрутов. `keyward status` при доступном SSH-плагине выводит число маршрутов и сокетов, ключи без привязки и предупреждения.

## Интеграция с OpenSSH и сокеты агента

Распечатайте рекомендуемую конфигурацию:

```sh
keyward ssh-config
```

Добавьте выведенный блок **в конец** `~/.ssh/config`, после блоков Host и алиасов:

```sshconfig
Match exec "/Users/you/.local/bin/keyward resolve %h %r %p"
  IdentityAgent /Users/you/.keyward/s/%h.sock
  IdentityFile /Users/you/.keyward/s/%h.pub
  IdentitiesOnly yes
```

Используйте именно абсолютные пути, которые напечатала ваша установка. `Match` должен находиться после блоков `Host`, чтобы `%h` был реальным хостом, а не алиасом до применения `HostName`. Абсолютный путь к CLI нужен, потому что `Match exec` запускается через `/bin/sh`, а у GUI-приложений `PATH` может отличаться.

`IdentityAgent` выбирает per-host socket. `IdentityFile` указывает на sidecar-файл `.pub`, содержащий **только публичный ключ**: при `IdentitiesOnly yes` OpenSSH должен видеть эту identity в списке; подпись всё равно делает агент, приватная часть в файл не записывается. Имя сокета получается из безопасно нормализованного hostname. Если маршрута нет, daemon недоступен или агент выключен, resolver сообщает «нет совпадения», и OpenSSH может вернуться к обычным файловым ключам.

Каталог сокетов закрыт от других пользователей (0700), сокеты имеют режим 0600. Не ослабляйте эти права. Необязательный общий сокет `~/.keyward/agent.sock` по умолчанию выключен, потому что предлагает все ключи и возвращает перебор идентичностей, от которого плагин уходит. Если включаете его для клиента, игнорирующего `ssh_config`, задайте `SSH_AUTH_SOCK` в путь из настроек SSH и помните, что общий агент может предлагать несколько ключей.

После изменения записей синхронизируйте vault; если требуется, запросите обновление маршрутов:

```sh
keyward reload
```

При блокировке vault сокеты закрываются.

## Настройки SSH

В **SSH → Settings** доступны:

- **Agent enabled** — включение/отключение ответов Keyward на запросы per-host агента; выключенный агент ведёт себя как отсутствующий.
- **Ask** — `Never` (при этом `kw-confirm` продолжает действовать) или `Always`; подтверждение проходит через Touch ID/approval flow.
- **Shared socket** — общий сокет со всеми ключами для инструментов, игнорирующих SSH config; по умолчанию выключен.
- **Health interval** — выключено, 15, 30, 60 или 180 минут. Проверка предлагает каждому ключу его хосты без создания подписи и показывает, принимает ли сервер ключ.

## Терминал, доверие к хостам и диагностика

Раздел SSH также предоставляет интерактивные SSH-сессии, страницы хостов и таблицу health-проверок ключей. Форма соединения может выбрать ключ по маршруту или явно указанный ключ. При первом подключении отпечаток host key показывается пользователю; изменившийся host key блокируется до разрешения проблемы. Доверие хранится локально/плагином и может быть связано с метаданными записи. Поле `kw-hostkey` позволяет явно закрепить ожидаемый fingerprint.

Для диагностики используйте `ssh -v host`, проверьте `keyward hosts`, настройки/status SSH в приложении и отображаемый отпечаток host key. Совпадение маршрута не означает, что сервер уже принимает публичный ключ: установите соответствующую публичную часть на сервере и проверьте health-результат.

## Permissions и доступ к данным

Manifest заявляет `entries`, `items_write`, `notices`, `ssh_sign`, `network`: чтение vault entries/SSH-ключей, изменение принадлежащих интеграции routing fields, уведомления, запрос подписи у core и сетевые SSH-подключения/проверки. Сам приватный ключ через API плагину не возвращается. `network` раскрывается при согласии пользователя, но не является сетевой песочницей для процесса на уровне ОС.

## Ограничения

Daemon подписывает OpenSSH-ключами Ed25519, RSA и поддерживаемыми ECDSA; аппаратные ключи не могут подписывать через Keyward. Агент хоста проверяет сообщения OpenSSH session binding, доказательство владения ключом сервера и заданный pin. Клиенты без session binding не передают агенту доказательство хоста; используйте также проверку ключа сервера в OpenSSH. Терминал имеет собственный процесс явного подтверждения доверия. SSH proxy-jump и certificate-сессии терминала не поддерживаются, `kw-cert` не выдаёт сертификаты. Приложение экспериментальное и не проходило независимый аудит.
